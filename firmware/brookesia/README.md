This directory contains the ESP-Brookesia firmware source for the
**Waveshare ESP32-P4-WIFI6-Touch-LCD-7, -8 and -10.1**. It drives the MIPI-DSI
touch panel, the ES8311 / ES7210 audio codecs, the OV5647 camera, the SD card
and ESP32-C6 hosted Wi-Fi.

## Platform configuration

| Item | Configuration |
| --- | --- |
| Host MCU | ESP32-P4NRW32, Rev3.x by default and Rev1.x through an overlay, 32 MB flash, 32 MB PSRAM |
| Display / touch | Waveshare 7, 8 and 10.1-inch portrait MIPI-DSI panels with a landscape UI, GT911 touch |
| Framework | ESP-Brookesia 0.6.0-beta2 (local `brookesia_core` component) |
| UI | LVGL 9.5.0 |
| Board support | ESP Board Manager 0.7.5, board `esp32_p4_wifi6_touch_lcd_x` from the Waveshare board definitions |
| LVGL adapter | `espressif/esp_lvgl_adapter` 0.7.4 |
| Wireless | ESP32-C6 over SDIO using ESP-Hosted 1.4.7 / `esp_wifi_remote` 0.14.5 |
| Voice assistant | `espressif/esp_xiaozhi` 0.1.3, ESP-SR 2.4.7 and xiaozhi-fonts 1.6.0 |
| Media | `espressif/esp_extractor` 1.0.7, `esp_new_jpeg` 1.0.2, `esp_video` 2.5.0 |

See the [repository README](../../README.md) for interfaces and pin assignments.

## Board support

Hardware is described with
[ESP Board Manager](https://components.espressif.com/components/espressif/esp_board_manager)
instead of a hand-written BSP. The base configuration of
`esp32_p4_wifi6_touch_lcd_x` is the 10.1-inch panel; the other panels are
selected with an amend:

| Panel | Resolution | Controller | MIPI-DSI lane rate | Amend |
| --- | --- | --- | ---: | --- |
| 7 inch | 720 x 1280 | ILI9881C | 1000 Mbps | `lcd_7_dsi_touch_a` |
| 8 inch | 800 x 1280 | JD9365 | 1500 Mbps | `lcd_8_dsi_touch_a` |
| 10.1 inch | 800 x 1280 | JD9365 | 1500 Mbps | none (base board) |

All panels use 2 data lanes, an 80 MHz DPI clock and three RGB565 frame
buffers with DMA2D. The `board` component is the layer the application uses:
it brings up display/LVGL, touch, backlight, audio, storage and Wi-Fi on top of
Board Manager. `gen_bmgr_codes` is generated by `idf.py bmgr`; do not edit it by
hand.

GT911 INT and RST are not connected to the SoC. The touch device probes I2C
address `0x5D` and then `0x14`, creates panel IO with the detected address and
reads touch data by polling. Because the SoC cannot reset the controller, the
board layer brings up the I2C bus before the panel and retries the touch probe
up to three times. Do not add an INT/RST address-selection sequence unless the
hardware contract changes separately.

## Build

### Requirements

Use ESP-IDF v5.5 (v5.5.6 is locked) with the `esp32p4` toolchain. Network
access to the ESP Component Registry is required. Use a data-capable USB cable
for flashing.

All commands below run from this directory. Starting from the repository root,
first generate the board code for your panel, then build. `-a` takes the amend
name and resolves it inside the board directory:

```sh
cd firmware/brookesia
idf.py --version

# 7 inch
idf.py bmgr -b esp32_p4_wifi6_touch_lcd_x -a lcd_7_dsi_touch_a
# 8 inch
idf.py bmgr -b esp32_p4_wifi6_touch_lcd_x -a lcd_8_dsi_touch_a
# 10.1 inch
idf.py bmgr -b esp32_p4_wifi6_touch_lcd_x

# Use the overlay for your panel: lcd-7, lcd-8 or lcd-10-1
idf.py -D SDKCONFIG_DEFAULTS="sdkconfig.defaults;sdkconfig.defaults.lcd-7" build
```

`gen_bmgr_codes` holds one panel at a time. Board Manager adds its generated
`board_manager.defaults` to the sdkconfig defaults automatically and resets
`sdkconfig` when the board changes. If CMake reports a missing `SRC_DIRS` entry
or the link fails in `gen_bmgr_codes`, the generated code is stale: rerun the
`idf.py bmgr` line for your panel (or `idf.py bmgr -x` to clear it first). Use
`idf.py bmgr`, not `menuconfig`, to switch boards.

### Panel overlays

Each panel has an overlay that selects its phone stylesheet. Use the overlay that
matches the `idf.py bmgr` line, because nothing checks that the two agree:

| Overlay | Panel | UI size | Stylesheet option |
| --- | --- | --- | --- |
| `sdkconfig.defaults.lcd-7` | 7 inch | 1280 x 720 | `CONFIG_PHONE_STYLESHEET_7_INCH` |
| `sdkconfig.defaults.lcd-8` | 8 inch | 1280 x 800 | `CONFIG_PHONE_STYLESHEET_8_INCH` |
| `sdkconfig.defaults.lcd-10-1` | 10.1 inch | 1280 x 800 | `CONFIG_PHONE_STYLESHEET_10_INCH` |

The panels are natively portrait. `BOARD_DISPLAY_ROTATION` in
`components/board/src/board_display.c` turns the UI 270 degrees into landscape, so
the stylesheet follows the rotated size. A stylesheet larger than the rotated UI
makes `addStylesheet()` fail and stops startup. The 1280 x 720 stylesheet is in
`main/Stylesheet1280x720Dark.hpp`.

### Silicon revisions

`sdkconfig.defaults` targets ESP32-P4 Rev3.x. For Rev1.x silicon, add
`sdkconfig.defaults.rev1_3` after the panel overlay:

```sh
idf.py -D SDKCONFIG_DEFAULTS="sdkconfig.defaults;sdkconfig.defaults.lcd-7;sdkconfig.defaults.rev1_3" build
```

The Rev1.x overlay runs PSRAM at 200 MHz instead of 250 MHz and disables the ISP
pipeline controller, so IPA auto exposure and auto white balance do not run on the
camera. Images for the two revision groups are not interchangeable: `esptool`
refuses to flash an image built for the other group. Check the chip first with
`esptool.py --chip esp32p4 -p PORT chip_id`.

### Switching panel or revision

All configurations share `build/` and `sdkconfig`, and `idf.py flash` writes
whatever was built last. `sdkconfig` takes priority over the defaults, so an
overlay has no effect on an existing `sdkconfig`. Clean up before changing the
panel or revision:

```sh
idf.py fullclean
```

Then delete `sdkconfig` and run the build command again.

### First full flash and partition changes

The first installation must write the bootloader, partition table, application,
ESP-SR model and SPIFFS resources:

```sh
idf.py -p PORT flash monitor
```

Erase the flash before a full flash when changing partition offsets or sizes,
upgrading from an older partition layout, or investigating stale model or
filesystem images:

```sh
idf.py -p PORT erase-flash flash monitor
```

When the partition layout, voice model and `spiffs/` resources are unchanged,
you can flash only the application:

```sh
idf.py -p PORT app-flash monitor
```

`app-flash` does not update `srmodels.bin`, `storage.bin` or the partition
table. Run a full `flash` after changing `partitions.csv`, WakeNet/model Kconfig,
xiaozhi-fonts, bundled music or prompt audio.

### Flash partitions

The layout is defined in `partitions.csv`; the partition table is at `0x9000`:

| Name | Type | Offset | Size | Purpose |
| --- | --- | --- | --- | --- |
| `nvsfactory` | data / nvs | `0xA000` | 200 KiB | Factory NVS data |
| `nvs` | data / nvs | `0x3C000` | 840 KiB | Wi-Fi, app settings and Xiaozhi state |
| `otadata` | data / ota | `0x10E000` | 8 KiB | OTA data (reserved) |
| `phy_init` | data / phy | `0x110000` | 4 KiB | PHY calibration data |
| `model` | data / spiffs | `0x111000` | 956 KiB | ESP-SR speech models (`srmodels.bin`) |
| `factory` | app / factory | `0x200000` | 8 MiB | Application |
| `storage` | data / spiffs | `0xA00000` | 6 MiB | Music, Xiaozhi prompts and font (`storage.bin`) |

`parttool.py` reads the table at `0x8000` unless told otherwise, so pass the offset,
for example to erase only `nvs`:

```sh
python $IDF_PATH/components/partition_table/parttool.py --port PORT --partition-table-offset 0x9000 erase_partition --partition-name=nvs
```

### Factory images

The application binary is named `esp32-p4-lcd-x-brookesia.bin`. The released
merged images are `ESP32-P4-WIFI6-Touch-LCD-7-FactoryOnly-260915.bin`,
`ESP32-P4-WIFI6-Touch-LCD-8-FactoryOnly-260820.bin` and
`ESP32-P4-WIFI6-Touch-LCD-10.1-FactoryOnly-260820.bin`. After building for a
panel, merge an image that flashes at offset `0x0`, for example:

```sh
(cd build && python -m esptool --chip esp32p4 merge_bin -o ../../ESP32-P4-WIFI6-Touch-LCD-7-FactoryOnly-260915.bin @flash_args)
```

## AIChats / Xiaozhi

AIChats uses `esp_xiaozhi` for the protocol. This project provides the UI,
activation, audio and lifecycle integration.

First use:

1. Configure WLAN in Settings.
2. Open AIChats. If the device is not associated with an account, it displays
   and announces an activation code.
3. Add the device in the [Xiaozhi control panel](https://xiaozhi.me) and enter
   the activation code.
4. When the page reaches standby, say the wake phrase. The default is
   "Ni Hao Xiao Zhi."

If the log reports `No speech model found` or `contains no compatible models`,
rebuild and perform a full flash to write both the partition table and
`srmodels/srmodels.bin`.

The local UI language and the preferred transport can be selected in this menu:

```text
idf.py menuconfig
  Xiaozhi Application
    Local UI language
      English
      Simplified Chinese
    Preferred Xiaozhi transport
      WebSocket
      Auto (prefer MQTT+UDP)
      MQTT+UDP
```

`sdkconfig.defaults` selects Auto. Auto chooses when a chat session is prepared:
MQTT+UDP if the OTA response includes an `mqtt` configuration, otherwise WebSocket.
It does not fall back at runtime when MQTT or UDP fails, so select WebSocket on
networks that block UDP.

The language option controls firmware-owned text only. It does not translate
conversation text, TTS or activation messages returned by the server. Local
strings are in `components/XiaozhiApp/XiaozhiLocalization.*`.

The ES7210 captures two microphones plus the ES8311 output as an echo
reference. AIChats feeds them to the ESP-SR AFE as `MMR` for AEC, wake word and
VAD, then sends 16 kHz mono Opus uplink; the playback chain converts server
audio as needed for the ES8311 output.

### MCP tools

AIChats registers device tools on the Xiaozhi MCP engine, so the assistant can
query and control the board by voice, for example "set the volume to 50" or
"what do you see?":

| Tool | Parameters | Function |
| --- | --- | --- |
| `device.audio.set_volume` | `volume` (0-95) | Set the speaker volume and save it |
| `device.audio.set_mute` | `mute` (bool) | Mute or unmute the speaker |
| `device.display.set_brightness` | `brightness` (20-100) | Set the display brightness and save it |
| `device.display.set_screen` | `on` (bool) | Turn the backlight off, or on again with the saved brightness |
| `device.get_status` | none | Volume, brightness and free memory |
| `device.network.get_wifi_status` | none | Wi-Fi enabled state, link state, SSID and IPv4 address |
| `device.get_info` | none | Chip, firmware and ESP-IDF versions, display size, microphones and Wi-Fi coprocessor |
| `device.system.reboot` | none | Restart the device after a few seconds, only when the user asks for it |
| `self.camera.explain_image` | `question` (string) | Take a photo with the OV5647 and answer a question about it through the server's vision service |

Volume and brightness use the same ranges and NVS storage as Settings, so
changes made by voice survive a reboot. Tools are registered in
`registerXiaozhiDeveloperTools()` in
`components/XiaozhiApp/XiaozhiDeveloperTools.cpp`, once for each MCP engine
before the Xiaozhi transport starts.

## Camera and media

Camera runs the OV5647 in its 800 x 800 RAW8 mode. The PPA cover-fills the
panel with the frame, rotating it a quarter turn when its orientation differs
from the panel's and cropping the source so that the scale factor lands on the
PPA's 1/16 steps.

VideoPlayer scans only `/sdcard/avi`; the `.avi` extension is case-insensitive.
AVI files in the SD card root and other containers such as MP4 or MOV are not
listed. The player demuxes AVI with `esp_extractor`, decodes MJPEG with the
hardware JPEG decoder (falling back to `esp_new_jpeg` for frames the hardware
cannot decode, such as progressive JPEG), and writes frames through the PPA
directly into the LCD frame buffer:

- Only MJPEG video is played. Only PCM audio is played; other audio formats
  are skipped and the video plays silently.
- Frames are not rotated. Frames are cropped around the centre to fill the
  screen, so encode videos in portrait for these panels.

Convert other videos with ffmpeg, for example:

```sh
ffmpeg -i input.mov -c:v mjpeg -q:v 5 -pix_fmt yuvj420p -r 24 -c:a pcm_s16le -ar 44100 -ac 2 output.avi
```

Raise `-q:v` (lower quality) or scale the video down if playback drops frames.

MusicPlayer plays the MP3 files in `/spiffs/music`. After changing tracks,
regenerate and flash `storage.bin`; `app-flash` alone does not update it.

## Development notes

- Apps register themselves with `ESP_UTILS_REGISTER_PLUGIN_WITH_CONSTRUCTOR`.
  `BOOT_APP_GROUPS` in `main/main.cpp` sets only the home-screen order and the
  boot stage shown while each group installs; registered apps not listed there
  are installed after the last group.
- New apps derive from `esp_brookesia::systems::phone::App` and implement
  `run()` and `back()`. Override other lifecycle functions according to
  resource ownership. Each component declares its own dependencies in its
  `idf_component.yml`; `main` keeps only the ones it uses directly.
- Board hardware is reached through the `board` component (`board.h` and its
  `board_*.h` headers); applications do not call Board Manager directly.
- To add an MCP tool, register it in `registerXiaozhiDeveloperTools()` (see
  [MCP tools](#mcp-tools)). Register only implemented tools that return real
  results; run long operations in an application task.
- Access LVGL objects on the LVGL thread or while holding the display lock
  briefly. On app shutdown, release its timers, tasks, queues, codec sessions,
  SD handles and LVGL objects.
- During playback, VideoPlayer enables the adapter's Dummy Draw and pauses LVGL.
  On exit, it stops playback and resumes LVGL rendering.

## Notes

- Use the LVGL lock only for UI operations. Run networking, SD scans, audio
  initialization, NVS access and model loading outside the lock.
- Model, font, prompt, music and partition changes require a full `flash`.
- Audio apps share one physical bus. Stop or hand off the codec session when
  switching between apps.
- The host component must remain compatible with the coprocessor firmware on
  the ESP32-C6.

`EXAMPLE_SHOW_MEM_INFO` in `main/main.cpp` is currently `true`, so periodic
SRAM/PSRAM statistics are enabled. The detailed log output is controlled
separately by `EXAMPLE_SHOW_MEM_INFO_LOG`.

When reporting an issue, include the panel size, ESP-IDF version, complete
reproduction steps and the first actual error in the logs.
